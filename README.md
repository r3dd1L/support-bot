# Telegram Support Bot

Support Bot — бот технической поддержки на Node.js и Telegraf с админ-панелью Telegram WebApp. Пользователь пишет боту в личные сообщения, бот переводит обращение в отдельный топик выбранной супергруппы Telegram и передает ответ администратора обратно пользователю.

Проект состоит из двух частей:

- серверной части и Telegram-бота — [bot.js](/workspaces/support-bot/bot.js);
- админ-панели — React-приложение в [webapp/](/workspaces/support-bot/webapp/).

Основные возможности:

- автоматическое создание и переоткрытие топиков для обращений;
- двусторонняя доставка текстовых и медиа-сообщений между пользователем и операторами;
- разделение тикетов по Telegram Forum Topics;
- ручное закрытие тикета командой `/close`;
- автоматическое закрытие неактивных тикетов;
- режим технического обслуживания;
- блокировка отдельных типов сообщений;
- антиспам с настраиваемым интервалом;
- блокировка и разблокировка пользователей;
- текстовые шаблоны по командам вида `/команда`;
- ключевые автоответы для входящих сообщений;
- богатые сообщения с форматированием, медиа и инлайн-кнопками;
- рассылка всем не заблокированным пользователям;
- статистика пользователей и тикетов в админ-панели;
- редактирование сообщений и настройки через Telegram WebApp.

## Как устроена работа бота

### Жизненный цикл обращения

1. Пользователь отправляет `/start` или любое другое сообщение боту в личном чате.
2. Бот проверяет готовность системы: наличие супергруппы, прав администратора и выбранной рабочей группы.
3. Если у пользователя нет открытого тикета, создается новый Forum Topic в выбранной супергруппе.
4. Новое обращение сохраняется в SQLite вместе с Telegram ID пользователя и ID топика.
5. Сообщение пользователя пересылается в соответствующий топик.
6. Администратор отвечает реплаем на сообщение в топике или использует шаблон `/команда`.
7. Текст, фото, документ, видео, аудио, голосовое сообщение, кружок, стикер или GIF пересылается пользователю.
8. При ручном `/close` или при истечении таймаута тикет закрывается и соответствующий топик закрывается в Telegram.
9. Следующее сообщение пользователя переоткрывает предыдущий закрытый топик. Если топик удалить или переоткрыть не удастся, создается новый.

Одновременно поддерживается только один открытый тикет для каждого пользователя.

### Группы и выбор рабочей группы

При добавлении бота в супергруппу он сохраняет группу в таблице `groups`. Бот отслеживает:

- статус добавления или удаления;
- обычные группы и супергруппы;
- наличие прав администратора;
- выбранную основную супергруппу.

Основная группа определяется так:

1. из значения `selected_support_group_id` в таблице `config`;
2. если оно не задано — из переменной окружения `SUPPORT_GROUP_ID`;
3. при первом добавлении бота она может быть выбрана автоматически.

Администратор может выбрать рабочую группу в интерфейсе Telegram после запуска `/start`, если доступно несколько супергрупп.

## Возможности Telegram-команд

- `/start` — приветствие, проверка блокировки и режима обслуживания, а для администратора — проверка и первичная настройка рабочей группы.
- `/admin` — открывает админ-панель через Telegram WebApp. Команда доступна только `ADMIN_USER_ID`.
- `/close` — закрывает тикет и Forum Topic, находясь в соответствующем топике супергруппы.
- `/имя_шаблона` — отправляет сохраненный шаблон пользователю активного топика. Доступно администраторам.

В ответах в теме сервиса админ-панель поддерживает команды шаблонов, а обычные ответы отправляются реплаем или обычным сообщением в соответствующий личный чат пользователя.

## Админ-панель

Админ-панель открывается по кнопке «Настройки» из Telegram-команды `/admin` или после выбора рабочей группы.

### Статистика

Показывает количество:

- всех зарегистрированных пользователей;
- заблокированных пользователей;
- созданных тикетов;
- закрытых тикетов.

Системная учетная запись бота исключается из пользовательской статистики.

### Пользователи

Список содержит имя, фамилию, username и Telegram ID. Для каждого пользователя можно переключить статус блокировки. Заблокированный пользователь не сможет создавать обращения и получает настроенное сообщение о блокировке.

### Настройки

Админ-панель редактирует:

- приветственное сообщение;
- сообщение после создания или отправки обращения;
- сообщение заблокированному пользователю;
- сообщение режима технического обслуживания;
- режим технического обслуживания;
- автоматическое закрытие тикетов;
- таймаут неактивности;
- текст при автоматическом закрытии;
- антиспам;
- интервал антиспама;
- текст предупреждения об антиспаме;
- блокировку текста, фото, документов, видео, аудио, голосовых сообщений, кружков, стикеров и GIF.

Настройки сохраняются в таблице `config` после нажатия «Сохранить все настройки».

### Шаблоны

Для шаблона задаются название, команда без `/` и содержимое. В топике супергруппы команда отправляет шаблонному пользователю текущего тикета. Шаблоны можно создавать, редактировать и удалять.

### Автоответы

Для автоответа задаются ключевое слово или фраза и ответное сообщение. Если текст входящего сообщения содержит ключевое слово без учета регистра, отправляется первый подходящий автоответ. Сработавший ответ дополнительно отмечается в топике с указанием ключевого слова и предварительным текстом ответа.

Ключевой поиск выполняется по тексту обычного сообщения или подписи к медиагруппе.

### Рассылка

Сообщение можно отправить всем пользователям в таблице `users`, кроме заблокированных. Перед отправкой интерфейс запрашивает двойное подтверждение. В ответе API указывается количество успешно отправленных сообщений.

## Редактор сообщений

Расширенный редактор поддерживает:

- текст;
- фото по Telegram `file_id`;
- видео по Telegram `file_id`;
- документ по Telegram `file_id`;
- HTML-разметку Telegram: `<b>`, `<i>`, `<u>`, `<code>`;
- инлайн-кнопки с URL;
- несколько рядов инлайн-кнопок;
- подключение сохраненных шаблонов;
- предпросмотр сообщения;
- проверку HTTP/HTTPS URL перед сохранением.

В текст можно вставлять переменные:

- `{имя}` — имя пользователя;
- `{фамилия}` — фамилия пользователя;
- `{ник}` — username с префиксом `@`, если он задан;
- `{id}` — Telegram ID пользователя.

Переменные заменяются перед отправкой. Для медиа сообщения задаются в формате JSON с `text`, `type`, `fileId` и `buttons`.

## Переменные окружения

Создайте файл `.env` в корне проекта:

```dotenv
BOT_TOKEN=123456789:AA...
ADMIN_USER_ID=123456789
SUPPORT_GROUP_ID=-1001234567890
WEBAPP_URL=https://example.com
PORT=3000
NGROK_AUTHTOKEN=ваш_ngrok_token
```

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен бота, полученный у `@BotFather`. Обязательна для запуска. |
| `ADMIN_USER_ID` | Числовой Telegram ID администратора. Только этот пользователь имеет доступ к `/admin` и административным callback-кнопкам. |
| `SUPPORT_GROUP_ID` | ID рабочей супергруппы в Telegram. Необязателен, если группа выбирается через `/start` или сохраняется в базе. |
| `WEBAPP_URL` | Публичный HTTPS URL собранной админ-панели. Обязателен для корректной работы WebApp. |
| `PORT` | Порт Express-сервера. По умолчанию `3000`. |
| `NGROK_AUTHTOKEN` | Токен ngrok для dev-режима. Используется скриптом запуска через ngrok. |

### Настройка бота в Telegram

1. Создайте бота через `@BotFather` командой `/newbot`.
2. Получите числовой Telegram ID администратора через любого известного бота для определения ID.
3. Создайте супергруппу и включите в ней Forum Topics.
4. Добавьте бота в супергруппу как администратора с правами на создание, закрытие и управление топиками.
5. Запишите ID супергруппы в `.env` или выберите ее через интерфейс бота.

Telegram WebApp принимает только публичный HTTPS URL. Для локального сервера обычно используется ngrok или иной HTTPS-туннель.

## Установка

Требования:

- Node.js 18 или новее;
- npm;
- поддерживаемая сборка `better-sqlite3`;
- Telegram-бот и супергруппа с Forum Topics.

Установка сервера и зависимостей админ-панели:

```bash
npm install
cd webapp
npm install
cd ..
```

Соберите админ-панель перед обычным запуском:

```bash
cd webapp
npm run build
cd ..
```

Собранные файлы помещаются в `webapp/dist`. Express раздает именно эту директорию на порту `PORT` или `3000`.

Создайте `.env` и укажите обязательные значения `BOT_TOKEN`, `ADMIN_USER_ID` и `WEBAPP_URL`.

## Запуск

### Обычный запуск

```bash
npm start
```

Запускается [bot.js](/workspaces/support-bot/bot.js): одновременно стартуют Telegraf polling, Express API и HTTP-сервер статических файлов админ-панели.

Админ-панель доступна по `http://localhost:3000` локально и по URL из `WEBAPP_URL` через обратный прокси или туннель.

### Запуск с ngrok

Для запуска сервера вместе с ngrok:

```bash
npm run dev
```

Скрипт [start-dev.js](/workspaces/support-bot/start-dev.js):

1. открывает туннель ngrok на порт `3000`;
2. записывает полученный HTTPS URL в `WEBAPP_URL` файла `.env`;
3. запускает `node bot.js`.

Перед запуском укажите `NGROK_AUTHTOKEN` в `.env`.

Для получения/обновления только ngrok URL можно запустить:

```bash
node get-ngrok-url.js
```

Этот вспомогательный скрипт запускает локальный сервер на порту `3000` и пытается записать публичный URL в `.env`.

### Режим разработки фронтенда

Для hot-reload админ-панели:

```bash
cd webapp
npm run dev
```

Vite запускается на порту `5173`. Запросы `/api/*` проксируются на `http://localhost:3000`, поэтому основной сервер из корня проекта должен быть запущен параллельно.

Сборка фронтенда:

```bash
cd webapp
npm run build
```

Предпросмотр сборки:

```bash
cd webapp
npm run preview
```

### Режим разработки бота с перезапуском

```bash
npm run dev:bot
```

Скрипт использует `nodemon bot.js`.

### Сброс основных настроек

```bash
node reset-config.js
```

Скрипт сбрасывает в таблице `config` следующие значения:

- `welcome_message`;
- `ticket_created`;
- `user_blocked`;
- `maintenance_message`;
- `maintenance_mode`.

При этом база данных и остальные настройки не удаляются.

## База данных

Файл базы создается автоматически рядом с [bot.js](/workspaces/support-bot/bot.js):

```text
support_bot.db
```

### Таблица `users`

Хранит зарегистрировавшихся пользователей:

- `id` — Telegram ID;
- `username`;
- `first_name`;
- `last_name`;
- `is_blocked`;
- `created_at`.

### Таблица `tickets`

Хранит обращения:

- `id`;
- `user_id`;
- `topic_id`;
- `is_closed`;
- `created_at`;
- `last_activity`;
- `closed_at`.

При старте проекта выполняется легкая миграция: если в таблице отсутствует `last_activity`, она добавляется, а существующим строкам назначается текущее время.

### Таблица `messages`

Связывает сообщения с тикетами:

- `ticket_id`;
- `from_user`;
- `message_id`;
- `created_at`.

### Таблица `config`

Пары ключ/значение для сообщений и режимов работы.

### Таблица `templates`

Сохраненные шаблоны:

- `name`;
- `command`;
- `content`.

### Таблица `auto_replies`

Автоматические ответы:

- `keyword`;
- `content`.

### Таблица `groups`

Известные группы, в которых находится бот:

- `id`;
- `title`;
- `is_supergroup`;
- `has_admin_rights`;
- `created_at`.

## HTTP API

Express-сервер работает на том же порту, что и бот.

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/api/stats` | Общая статистика |
| `GET` | `/api/users` | Список пользователей |
| `POST` | `/api/users/:id/toggle-block` | Переключить блокировку пользователя |
| `GET` | `/api/config` | Получить все настройки |
| `POST` | `/api/config` | Сохранить переданные пары настроек |
| `GET` | `/api/templates` | Список шаблонов |
| `POST` | `/api/templates` | Создать шаблон |
| `PUT` | `/api/templates/:id` | Обновить шаблон |
| `DELETE` | `/api/templates/:id` | Удалить шаблон |
| `GET` | `/api/auto-replies` | Список автоответов |
| `POST` | `/api/auto-replies` | Создать автоответ |
| `PUT` | `/api/auto-replies/:id` | Обновить автоответ |
| `DELETE` | `/api/auto-replies/:id` | Удалить автоответ |
| `POST` | `/api/broadcast` | Запустить рассылку |

Пример ответа статистики:

```json
{
  "totalUsers": 12,
  "blockedUsers": 2,
  "totalTickets": 20,
  "closedTickets": 7
}
```

Пример обновления настроек:

```bash
curl -X POST http://localhost:3000/api/config \
  -H "Content-Type: application/json" \
  -d '{"maintenance_mode":"1","maintenance_message":"Бот временно недоступен"}'
```

## Автоматическое закрытие и антиспам

Проверка неактивных тикетов выполняется каждую минуту. Тикет считается неактивным, если с момента `last_activity` прошло больше `auto_close_minutes` минут и включена опция `auto_close_enabled`.

Для входящих сообщений пользователя антиспам ограничивает частоту, если включена опция `antispam_enabled`. Минимальный интервал задается в секундах параметром `antispam_interval`. Сообщения внутри одной Telegram-media group не считаются отдельными спам-сообщениями.

## Поддерживаемые медиа и альбомы

Пользовательские и администраторские медиа-сообщения дополнительно группируются по `media_group_id`. Альбомы пересылаются как Telegram media group с задержкой сборки элементов.

Поддерживаются:

- текст;
- фото;
- документы;
- видео;
- аудио;
- голосовые сообщения;
- видеосообщения-кружочки;
- стикеры;
- GIF/анимации;
- подписи к медиа.

Админ-панель позволяет сохранять фото, видео и документ как контент с Telegram `file_id`.

## Типичные ошибки

- **Бот не запускается** — проверьте `BOT_TOKEN` в `.env`.
- **Нет доступа к `/admin`** — проверьте точное числовое значение `ADMIN_USER_ID`.
- **Бот не создает тикеты** — добавьте бота в супергруппу с Forum Topics, выдайте права администратора и выберите рабочую группу.
- **Telegram не открывает админ-панель** — укажите публичный HTTPS URL в `WEBAPP_URL`.
- **Админ-панель не получает API** — запустите сервер на порту `3000` и проверьте прокси Vite.
- **Ngrok не запускается** — проверьте `NGROK_AUTHTOKEN`.
- **`better-sqlite3` не устанавливается** — проверьте совместимую версию Node.js и установите переподготовленные бинарники на платформе выполнения.
